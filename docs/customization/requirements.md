# 产品需求确认记录（问答中）

## 已确认信息

- 产品方向：多编码 Agent 编排，不是通用聊天机器人平台。
- 基座选型：Orchestrator.inc，克隆到 E:\code\agent-orchestrator 并在独立分支改造。
- 终端形态：以 Windows 本地使用为起点，桌面界面希望接近 Codex 的会话体验。
- 交互重点：查看各 Agent 的执行过程；执行期间能与指定 Agent 交互。
- 工作方式：先建立基础骨架，再逐问逐答确认需求，最后产出详细设计。
- **控制模式（Q1）：混合模式。** 主控 Agent 默认自动规划、拆分和分配任务；用户可以随时介入指定 Agent 的会话，补充指令、暂停或调整任务分配，也可以手动创建任务。具体干预语义和审批边界后续继续确认。

## 待确认问题

1. **执行器范围（Q2）：** 首发必须接入哪些编码 Agent？例如 Codex CLI、Claude Code、OpenCode、Gemini CLI，或其他执行器。
2. **交互语义：** 执行中对话是消息排队、即时 Steer，还是支持取消、重规划？
3. **协作模型：** Agent 之间允许自行协调到什么程度？
4. **代码处理：** Worktree、审查、测试、自动提交和推送的审批边界是什么？
5. **项目范围：** 首版单仓库还是多仓库；本地执行还是需要远程 Worker？
6. **UI 取舍：** 以 Codex 风格重排为主，还是保留 Orchestrator.inc 多面板工作台？
7. **质量与约束：** 最大并发、Token 预算、模型供应商、隔离权限与恢复策略。
