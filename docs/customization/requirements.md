# 产品需求确认记录（问答中）

## 已确认信息

- 产品方向：多编码 Agent 编排，不是通用聊天机器人平台。
- 基座选型：Orchestrator.inc，克隆到 `E:\code\agent-orchestrator` 并在独立分支改造。
- 终端形态：以 Windows 本地使用为起点，桌面界面希望接近 Codex 的会话体验。
- 交互重点：查看各 Agent 的执行过程；执行期间能与指定 Agent 交互。
- 工作方式：先建立基础骨架，再逐问逐答确认需求，最后产出详细设计。

## 待确认问题

1. **控制模式**：默认由主控 Agent 自动规划与分发、人工逐步分发，还是两者结合？（本轮提问）
2. **执行器范围**：首发必须接入哪些 Agent（Codex、Claude Code、OpenCode、其他）？
3. **交互语义**：执行中对话是消息排队、即时 Steer，还是支持取消、重规划？
4. **协作模型**：Agent 之间允许自行协调到什么程度？
5. **代码处理**：Worktree、审查、测试、自动提交和推送的审批边界是什么？
6. **项目范围**：首版单仓库还是多仓库；本地执行还是需要远程 Worker？
7. **UI 取舍**：以 Codex 风格重排为主，还是保留 Orchestrator.inc 多面板工作台？
8. **质量与约束**：最大并发、Token 预算、模型供应商、隔离权限与恢复策略。
