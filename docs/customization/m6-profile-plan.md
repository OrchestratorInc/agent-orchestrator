# M6-07 Workflow 自定义供应商引用闭环

状态：已确认首版缺口，纳入M6可自主开发范围。依据：[requirements.md](requirements.md) Q9、[design.md](design.md) §12、[m5-design.md](m5-design.md)模型与profile传递要求。统筹定义行为和验收，执行方自行选择实现方式与顺序。

## 现场事实

- backend/internal/service/workflow/service.go 的Create对非空Profile返回WORKFLOW_PROFILE_UNSUPPORTED。
- 同目录planning.go把非空Profile视为PLAN_AGENT_INVALID；replanning.go已有Profile输入。
- backend/internal/service/execution/coordinator.go与local_gateway.go也拒绝非空Profile。
- backend/internal/ports/execution.go已存在Profile字段，不能只放开创建校验后仍在执行层丢失或拒绝。
- 现有原生Agent模型/认证发现和运行设置应优先复用。service/capability的StaticProfile是只读能力展示目录，不能当作可信供应商配置或执行授权。

## 必须形成的用户行为

用户可以在Workflow中引用自己配置的供应商/profile；创建、自动规划产生的任务、Stop & Replan、执行与持久恢复使用一致且可追踪的选择。公开字段保存和回显引用及非敏感模型信息，凭据不得进入任务正文、日志、审批摘要、Renderer或命令行展示。

原生配置仍可用；未选择profile的既有任务保持原有行为。Adapter只映射实际支持的模型、API URL、认证、effort和上下文字段，不能为了统一形状静默忽略或降级。四个首发Adapter分别给出经代码/协议证据支持的能力；不支持的组合在产生执行副作用前明确拒绝。只增加拒绝说明不构成本工作包完成，至少须存在可实际使用的受支持供应商引用链路，并明确四Adapter各自边界。

供应商选择不构成权限授权：profile中的权限、沙箱、hook或任意命令设置不能覆盖现有只读Planner、审批、受限执行及工作区边界；不能因引用受支持而执行额外配置副作用。

引用不存在、配置失效、Adapter不匹配或配置在批准/启动之间改变时，不能误用另一个配置或转用默认凭据。恢复与重试保留任务身份、既有Session/Worktree、预算及准入约束；配置不确定时给出可追踪失败，不重复Spawn。

用户入口需覆盖选择、保存、清除、详情回显和失败反馈，并使用现有UI与daemon边界。配置和凭据的存储/选择沿现有可信机制；若现有机制不足，先向统筹给出最小接口与信任边界提案，由统筹补充任务设计，不建立无关的供应商管理平台。

## 已确定的最小存储与信任边界

执行方已核实没有现成可信供应商profile存储。统筹据design§12确认采用以下边界，属于原任务内的实现决策，不需要用户重新配置真实环境：

- 复用现有qualitygate宿主登记表的装配方式，在AO_DATA_DIR下读取专用供应商登记文件。文件只含严格白名单的路由参数、显示名称和凭据环境变量名，不保存凭据值；不存在文件时保持原生默认行为，不自动生成真实用户配置。JSON未知字段、重复身份、无效地址或不支持的组合必须整体拒绝，不能接受合法前缀后忽略坏项。
- 注册来源仅为可信宿主配置；Agent、任务正文与普通HTTP输入不能提交任意URL、环境变量名、路径或启动字段来创建注册项。产品UI本工作包只选择已有项、显示能力与错误，不增加写配置或读取任意环境变量的接口。配置示例写在Markdown用户指南中，不提交配置文件。
- 第一条可用映射采用Codex，其他三个首发Adapter对非空平台profile明确报告当前不支持；四Adapter的原生路径保留。此为初版可用覆盖范围，矩阵需明确差异，不能声称四Adapter自定义路由均已通过。后续只有实际支持的映射才扩展。
- Workflow持久保存引用和规范化配置摘要，并把身份带到规划、Claim、实际启动、重试和恢复链路。启动/恢复所用的可信登记内容必须与任务固定的摘要一致；配置变化、丢失或环境变量未满足时显式失败，禁止切到默认凭据或另一个Provider。缓存生命周期和具体字段设计由执行方决定，须有跨进程重开后的证据。
- 凭据只由后端在最后需要的启动环境/协议通道中解析，限定到登记的Provider；不能落盘到会话指令、公开API、日志、审批、命令行或Renderer。可公开目录只含选择所需非敏感信息，不回传宿主配置路径与凭据值。
- 凭据环境变量使用平台专用 `AO_WORKFLOW_CREDENTIAL_` 前缀，登记表拒绝公用原生密钥名。所有Agent最终进程环境移除该命名空间及其大小写别名，选定的受支持启动仅在可信解析后注入当前密钥；普通原生凭据保留原行为。此为SV-M6-03审查后收紧的新功能边界，不自动修改用户真实环境或配置；Markdown指南说明配置方式。
- daemon启动时在产生子进程前接管专用凭据到只读内存并从自身可继承环境移除，避免遗漏的默认继承路径外发；不改变父进程或系统环境。平台凭据更新通过更新启动环境并重启daemon生效；重启重新认证，旧宿主身份不匹配仍拒绝接管。登记表路由字段仍在解析时检查漂移。
- 白名单只影响供应商路由、模型及经Adapter验证的effort/上下文能力。权限、沙箱、hook、MCP、任意命令和任意环境覆盖均不属于profile能力，不能直接透传整份原生profile来扩权。地址/字段验证不接受内嵌账号密码、控制字符和配置注入；Loopback本地供应商按实际设计能力处理，不凭此扩展daemon监听或外联权限。
- 所有开发验证使用C盘scratch AO_DATA_DIR、假环境凭据和离线执行器。不得读取用户真实密钥、修改真实登记表或原生CLI配置；真实Provider成功请求继续独立未验。

## 自定义路由的认证证据决策

现有capability将仅配置凭据与真正授权分开；固定profile摘要必须进入能力请求和证据复用身份，不能沿用仅按Harness取得的默认账号结论。证据还须对应本次所用凭据身份，秘密或秘密摘要不得出现在公开诊断中。安装、协议版本、资源、预算、只读Planner等独立门禁继续有效。

GET /models返回200不足以证明凭据有效，因为目录可能公开；现有authprobe/connection.go明确保留同一边界。其VerifyConnection发送一token生成请求，不能作为本轮无真实Provider授权下的开发验证。可实现非生成式验证，但必须有真正的鉴权证据，例如同一目标拒绝无凭据/明确错误凭据，而当前profile凭据成功且目标模型存在，或已有可信的供应商身份协议。公开目录对照也成功、缺目标模型或不支持这种验证时保持configured/unknown或blocked，禁止伪造READY。该验证只证明所选身份和目录权限，不代表真实推理额度、计费或Responses生成已经验收。

探测只针对宿主登记的目标，拒绝重定向，有明确超时、响应大小与重试上限；复用既有缓存/去重边界避免Scheduler每轮重复外呼。失败诊断不保留响应正文或密钥，不回退其他账号。列表展示不得为了读取目录而自动探测真实供应商。测试覆盖公开目录不验证密钥、错误凭据、错误模型、401/403、超时、重定向、配置/凭据身份不匹配、无默认原生账号的成功选定profile路径；仅本地假服务与假凭据，真实Provider验收继续暂缓。

## 验收证据

1. 受支持引用从正式HTTP/服务入口到真实Manager装配、Adapter启动参数或协议选择的离线端到端证据；使用假凭据和Fake执行器，不调用收费Provider。
2. 所选profile的认证与协议能力证据不能由默认原生账号READY冒名，也不能只因缺少默认原生账号而错误拒绝已有合法profile证据；验证这两种相反条件，禁止伪造READY或放宽资源/权限准入。未知引用、跨Adapter引用、不支持字段、配置变化及持久恢复等失败路径；断言没有偷偷改用默认配置、没有越过准入或权限边界，也没有重复执行。
3. 未选择profile和清除选择后的既有路径回归，包含Planner与Replan；前端选择/回显/错误行为以及API类型一致。
4. 凭据不出现在公开响应、可见日志和任务/审批正文；用户原生配置未被修改。实际命令、退出码、影响文件及未验范围写入m6-report.md与m6-coverage.md。
5. 涉及API时按仓库规则生成并验证spec/types，涉及数据库时新增迁移并通过已有存储回归；不手改生成文件，不覆盖旧migration。

## 执行边界

沿用M6唯一执行会话及串行高I/O窗口，复用C盘隔离环境。不得修改真实.codex/.claude配置、使用真实凭据、发送真实Provider请求或提交配置文件；不增加并发。Windows Hello、真实Provider和安装升级保持独立未验，不阻塞上述离线开发，也不能被本工作包的测试替代。方案若需要真实配置变更或用户选择，先完成其余可自动部分并明确留下缺口。
