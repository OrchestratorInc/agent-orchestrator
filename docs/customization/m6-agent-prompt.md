# M6 执行会话派发说明

本阶段只在 M5 独立验收通过并完成本地提交后启动。派发消息应包含实际 M5 提交 SHA 与独立验收报告位置。

在 `E:/code/agent-orchestrator` 完成 [M6 计划](m6-plan.md) 的稳定性、Windows 候选交付、恢复验证及用户文档。先核对根目录 AGENTS/CONTRIBUTING 和现有交付状态，再读取 M5 报告、验收记录与总设计需求覆盖。

会话和子 Agent 全部使用 Astra，思考强度按任务难度选择；不使用 codexhost-delegation。你自行决定实现、自测和内部工作组织。统筹负责独立验收、缺陷返修派发及验收后的阶段提交。

交付内容必须包括：首版 Q1～Q10 实际覆盖矩阵、恢复/权限验证、Windows 候选与隔离升级证据、用户指南和故障手册、完整适用检查的命令/退出码/日志位置、候选 SHA/hash、未验范围和具体外部阻断。缺少核心功能时给出源码依据并补齐受影响交付，不用文档声明代替实际接线。

保护现有 dirty、原生 CLI 配置、真实 AO 数据和安装。不 Push/Merge/发布、不提交配置或构建产物。测试仅用隔离数据、Fake Provider 和临时 Git；M0-05 真实 Provider 仍须另获授权。真实 Windows Hello 人工步骤、签名凭据和正式发布不得伪造或绕过。

完成可自主执行的工作后，提供具体候选与剩余授权需求。`m6-report.md` 由你维护，`m6-acceptance.md` 由统筹维护。未满足完整发布门禁时明确报告未通过，不把离线候选验证改写成正式发布成功。
