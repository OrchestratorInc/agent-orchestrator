## Unfinished release requirements

These are not certified by this review or by existing tests. They remain release blockers in the staged plan, rather than reasons to broaden native-account changes:

- M0/M1: encrypted persistence across every credential write, quarantine and verification before publishing login/import results, durable cancellation/deletion fences, refresh/reconnect generations, and restart recovery.
- M2/M3: explicit per-session selection, connection-mode persistence, live binding-revision authorization, switching transactions, in-use removal, and proof for repeated requests on long-lived connections.
- M0/M4/M5: exact CLI-version compatibility, live native coexistence, full session workflows, cross-platform packaging, and measured responsiveness.

In particular, this review does not prove cancellation/deletion fences against late upstream credential writes, revocation after deleting and re-adding a credential, or native/managed connection-mode persistence. Existing native sessions must not become managed solely because the provider default was enabled. The current unbound-session path still needs M2's durable mode record. API-key refresh/disable are not advertised as working. Snapshot epochs and concurrent refresh completion ordering remain M4 work. These limitations prevent treating the existing opt-in surface as the completed specification.
