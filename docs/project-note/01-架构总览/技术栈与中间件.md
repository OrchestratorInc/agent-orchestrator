## 后端依赖（刻意的极简）

选型原则见 `docs/stack.md`：**能用标准库就不加依赖**。

| 领域 | 依赖 | 用途 |
|---|---|---|
| HTTP 路由 | `go-chi/chi/v5` | 轻量路由 + 中间件，不引入大框架 |
| WebSocket | `coder/websocket` | 终端流（`/mux`） |
| PTY | `creack/pty` | PTY 后端会话 |
| 终端视口 | `unixshells/vt-go` | 分离式 PTY host 的当前屏模型（用于安全判定） |
| SQLite | `modernc.org/sqlite`（纯 Go，无 CGO） | 唯一持久化；`database/sql` 之上可换驱动 |
| SQL 生成 | `sqlc` | `queries/*.sql` → `storage/sqlite/gen/` |
| 迁移 | `pressly/goose/v3` | SQL 迁移，只增不改 |
| CLI | `spf13/cobra` + `pflag` | `ao` 命令树 |
| 日志 | 标准库 `log/slog` | 结构化日志 |
| OpenAPI 生成 | `swaggest/openapi-go`、`jsonschema-go`、`yaml.v3` | 从 Go DTO 生成 spec |
| 平台 | `Microsoft/go-winio`、`aymanbagabas/go-pty` | Windows 命名管道 / ConPTY |
| 其它 | `google/uuid`、`golang.org/x/{sync,sys,text,image}` | ID、并发原语、平台调用 |

**明确拒绝**：GORM、Gin/Fiber、go-git（改用 `git` CLI 以匹配用户真实行为）、viper/koanf、Temporal/NATS/Kafka/Redis、插件运行时。理由逐条见 `docs/stack.md`。

## SQLite 必备 PRAGMA

`backend/internal/storage/sqlite/db.go` 建立连接时设置：

```sql
PRAGMA journal_mode = WAL;
PRAGMA busy_timeout = 5000;
PRAGMA foreign_keys = ON;
PRAGMA synchronous = NORMAL;
PRAGMA journal_size_limit = 33554432;  -- 32 MiB，per-connection
```

单写多读模型：daemon 是唯一写入者，HTTP/SSE/终端为读方。

## 时间与时钟

- 所有定时器周期为**常量 + 可注入 `Clock`/`Tick`**，测试通过注入缩短周期，不靠 sleep。
- 迁移 ID 为 UTC `YYYYMMDDHHMMSSsss`，由 `npm run migration:create` 生成。
