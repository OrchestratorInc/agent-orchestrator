# 已知问题与陷阱

实测踩过的坑，按「现象 → 根因 → 规避」组织。全部有仓库内证据（文档、测试或代码注释）。

## P1 · 前端与打包

### 1. SSE 连接吃光 Chromium 每 host 6 条连接

- **现象**：Settings 等普通请求无故排队；页面看起来「卡住」。
- **根因**：每条 `EventSource` 长占一条 HTTP/1.1 连接；renderer 同时开 3–5 条流，只剩 2–3 条给其他请求。
- **规避**：事件流走 `ao-events.localhost`（独立 host），且**仅当** daemon 报告它也服务 `[::1]` 时启用——否则 `::1` 上的其他进程会收到流。
- **位置**：`frontend/src/renderer/lib/api-client.ts`。

### 2. 原生模块 ABI 混用（Node 24 vs Electron 44）

- **现象**：Node 测试全绿，桌面应用加载原生模块失败。
- **根因**：Node 24 需 ABI 137，Electron 44.7 需 ABI 149。
- **规避**：Node 测试通过的 `.node` **不能**当桌面产物；打包必须由 Forge 按 Electron ABI 重建。缺预编译包时保留源码编译错误，不降低 ABI 校验。
- **证据**：`docs/customization/troubleshooting.md`「Node 与 Electron 原生模块 ABI」。

### 3. `unzip` 验证 macOS 产物 → 假失败

- **现象**：签名校验失败，但产物其实是好的。
- **根因**：裸 `unzip` 破坏 app bundle 的签名封印。
- **规避**：只能用 `frontend/scripts/verify-mac-artifact.sh`（`ditto -x -k` + `codesign --verify --deep --strict` + `spctl -a -vv -t exec` + `xcrun stapler validate`）。
- **补充**：`spctl` 不带 `-vv` 时成功也不打印任何东西。

### 4. Electron packager 的 TLS 抖动

- **现象**：完整构建 exit 1，`Client network socket disconnected before secure TLS connection was established`。
- **根因**：packager 内嵌 `@electron/get` 即使命中 ZIP 缓存仍联网取 SHASUMS；失败会回退下载 ZIP。日志无 URL/请求序号。
- **规避**：不要在没有根因修复或条件变化时盲重试；独立下载链成功**不能**替代完整构建。

### 5. 打包验收的数据隔离

- **现象**：设了 `AO_DATA_DIR` 仍污染用户数据。
- **根因**：打包版 Electron `userData` 固定为 `~/.ao/electron`，与 `AO_DATA_DIR` 无关。
- **规避**：未建立有效隔离环境前，不要启动候选安装包做验收。

## P2 · 测试环境隔离

### 6. Windows 下 `HOME`/`TEMP` 不足以隔离用户目录

- **根因**：Go 的 `os.UserHomeDir()` 在 Windows 读 `USERPROFILE`。
- **规避**：测试子进程必须同时设 `USERPROFILE`、`HOME`、`AO_*`、`AppData`、`XDG`，并禁止继承真实凭据。
- **事故**：旧全量检查曾把 8 条测试工作区记录写进真实 `.claude.json`；此后要求核对真实配置哈希/mtime，漂移即 exit 97 中止。

### 7. Chrome native-messaging 注册表无法用 HOME 隔离

- **键**：`HKCU\Software\Google\Chrome\NativeMessagingHosts\dev.ao.browser_bridge`
- **根因**：HKCU 属于用户注册表，HOME/USERPROFILE 隔离无效。
- **规避**：测试必须显式注入目录模式或内存 fake（`testInstaller`）；生产 `Installer` 未提供工厂时才走平台默认。**不要**为了复现旧失败先写真实注册表。

### 8. ConPTY 网格断言依赖系统语言

- **现象**：三轮失败，本机中文输出。
- **根因**：旧断言只匹配 `mode con` 的英文 `Lines/Columns`。
- **规避**：用 Windows API 读真实行列尺寸并核对退出码；不改系统语言/代码页或跳过断言。

### 9. Windows symlink 权限

- **现象**：`A required privilege is not held by the client`。
- **规避**：保留失败与「权限能力未验」结论，**不要**擅自改系统权限；路径转义/分隔符的断言问题要单独修复，不能与权限不足混为一谈。

### 10. Go 测试缓存掩盖未执行

- **现象**：158/170 包报 `(cached)` 实际未跑。
- **规避**：CI 一律加 `-count=1`（编译仍可缓存）。

## P3 · 后端行为陷阱

### 11. 失败探针不是死亡

- `ProbeFailed` / `AccessDenied` / 查询异常 → 保留占位、保留锁/描述符/run-file。
- 误判会杀掉用户正在进行的会话；终止需 5 项条件同时满足（见 `03/会话生命周期与终止判定.md`）。

### 12. 探针大面积同时失败是故障，不是 N 次死亡

- `reaper` 熔断：`dead >= 5` 且 >50% 被探测会话 → 本批全部降级为 `ProbeFailed`。

### 13. 把未知当成功/失败都会出错

- 工作流绑定：网关返回空 session 是 `spawn_unknown`（未知），不是成功；readiness 未知不能为新会话背书。
- 为了让 lint 的 `nilerr` 过而把 unknown 改成否定、或解除 `Frozen` 栅栏，都是错误修复。

### 14. `sendMu` 与 generation 的关系

- 一个 `*Controller` 的 generation 在构造时固定，永不改变；替换控制器是**另一个对象**。所以「持有对象即持有其 generation」——不要给 generation 加锁或试图在锁内重读。

### 15. 分片上报不能整块覆盖

- Chat 的 `account` / `threadState` / `usage` / `mcpServers` 都是**分片**上报；整块替换会清空前一片（例如把百分比表变成裸 token 数）。

### 16. 全行写入不能回退旧读字段

- 会话行有 `Revision`；旧读的全行写入不能把 title 或已替换的临时分支写回。

## P4 · 工具与流程

### 17. `npm run api` 的类型生成步骤曾无法解析命令入口

- 现象：`api:spec` 成功，`openapi-typescript` 入口未解析，exit 1。
- 规避：直接执行已缓存的 7.4.4 CLI 生成（已验证产物 SHA 不变）；不要重装或改依赖配置。

### 18. lint 的 CRLF 误报

- 183 个 goimports 问题中 181 项仅因 CRLF；LF 副本仍有 27 项真实问题。
- 规避：不要用「换行差异」笼统解释全部 lint 失败。

### 19. 降级检查的语义边界

- `LiveTarget` 的观察失败只闭锁**当前操作**，不证明死亡。
- Gateway 只 wrap 本层权威分类；扩大 unwrap 会把 `UNKNOWN` 误判为 `failed_confirmed/spawn_refused`。

### 20. Git 只读审计遇到 dubious ownership

- 源码只读审计不必使用产品测试的隔离 HOME；改用验证过的输入 HEAD + 冻结清单核对即可。
- **不要**修改 global `safe.directory`、目录所有者或添加通配信任。
