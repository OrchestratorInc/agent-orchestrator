# 核心功能模块

## 模块全景

功能分两大块：**上游单 Agent 基座**（session / terminal / PR / 观测）与**本地新增的多 Agent 工作流层**（workflow / scheduler / execution / quality / collaboration）。

| 模块 | 代码位置 | 职责 | 边界（不做什么） |
|---|---|---|---|
| **会话管理** | `internal/session_manager/`（108 文件，`manager.go` 317 KB） | spawn / kill / restore / send / 控制器切换 / 异步 provision | 不实现 agent 协议细节（交 adapter） |
| **生命周期** | `internal/lifecycle/`（`manager.go`、`steps.go`、`reactions.go`） | 归约观察为耐久事实；状态机；终止护栏；nudge 发送 | 不做轮询（交 observe） |
| **Chat 服务** | `internal/service/chat/`（137 文件） | 会话投影、turn/message、审批、input、压缩、回滚、side chat、持久 host 接管 | 不建 PTY 运行时句柄 |
| **项目与工作区** | `internal/service/project/`、`adapters/workspace/{gitworktree,scratch,router}` | 项目 CRUD/配置；每会话独立 worktree 或 AO 托管目录 | 不强制删除脏 worktree |
| **PR / Review** | `internal/service/pr/`、`review/`、`adapters/scm/{github,gitlab}`、`adapters/reviewer/`（22 个） | PR 事实观察、合并、评论解析；独立审查执行 | 不做原始 CI 日志传输 |
| **观测** | `internal/observe/{scm,reaper,usage,activity,artifacts,automations,ownership,trackerintake}` | 外部状态轮询与归约 | 不直接改展示状态 |
| **终端** | `internal/terminal/`、`adapters/runtime/`、`httpd/terminal_mux.go` | `/mux` WS 复用；native PTY / ConPTY / tmux | 不是 Chat 会话的控制器 |
| **Agent 接入** | `internal/adapters/agent/`（472 文件，38 harness）+ `chatdriver/`（24 个 driver） | 每个 harness 的启动命令、hook、活动识别、能力探针 | 不跨系统隔离声明（原生模式≠沙箱） |
| **工作流** | `internal/service/{workflow,scheduler,execution,collaboration,intervention,qualitygate,qualityreview,taskcommit,integration,report}` | DAG 计划、准入、执行绑定、协作消息、干预、质量门禁、集成 | 只通过既有 session manager/worktree/review 端口调用 |
| **桌面端** | `frontend/src/{main,renderer,preload}` | UI、daemon 监管、浏览器视图、更新器 | 不含 daemon 业务逻辑 |
| **移动端** | `packages/mobile/`（app 39 文件 + lib 631 文件） | 同一 daemon 的第二个 renderer | 不实现 provider 或生命周期策略 |
| **共享 UI** | `packages/product-ui/` | 桌面与移动共用的视图模型（board/inspector/composer） | 不做平台专属逻辑 |
| **Cloud** | `contracts/cloud/openapi.yaml`、`packages/cloud-client/` | 控制平面契约与类型客户端（控制平面在私有仓） | 本仓不实现控制平面 |

## Harness 三类注册表（**互不自动扩展**）

| 注册表 | 数量 | 位置 | 说明 |
|---|---|---|---|
| Worker / TUI-Chat 会话 | 38 | `internal/adapters/agent/registry/registry.go` | 加 harness = 只改 `Constructors` 一处 |
| Chat driver | 24 | `internal/adapters/chatdriver/` | Codex app-server、各类 ACP（claude/qwen/copilot/pi/omp/opencode/kimi/kimchi/droid/gemini/agy/cursor/deepseek/commandcode/unreal/native/scripted 等） |
| Reviewer | 22 | `internal/adapters/reviewer/registry.go` | 与 worker 集**刻意分离**：在此加 reviewer 不会扩大 `AgentHarness` 词表 |

Harness 名称常量在 `internal/domain/harness.go`（39 个），包括 `claude-code`、`codex`、`aider`、`opencode`、`opencode-v2`、`grok`、`droid`、`amp`、`agy`、`crush`、`cursor`、`qwen`、`gemini`、`copilot`、`goose`、`auggie`、`continue`、`devin`、`cline`、`kimi`、`muse`、`kiro`、`kilocode`、`vibe`、`pi`、`kimchi`、`prime-agent`、`autohand`、`omp`、`fx`、`unreal-agent`、`codewhale`、`mimo-code`、`memcode`、`deepseek-harness`、`openhands`、`command-code`、`hermes`、`fake`。

**能力判断必须查注册表，不能靠推断**：Cursor 同时有 Chat 和 TUI adapter，但「跨接口历史交接」是**独立能力**，不能因为注册了 Chat 就认为可切换。

## 接口模式（interface mode）

每个会话只有一个已提交模式，由 `sessions.mode` 决定：

| 模式 | 控制器 | 运行时 | 会话内容 |
|---|---|---|---|
| `tui` | agent adapter 启动的真实 CLI，跑在 PTY/ConPTY（tmux 为 legacy/fallback） | 有 runtime handle | 终端像素历史 |
| `chat` | chat driver（Codex app-server / ACP） | **无** agent 运行时句柄 | 耐久 conversation 投影 |

Chat 会话仍可开**会话级 shell 终端**做逃生舱，但那些 shell 是独立资源，不成为 agent 控制器。

## 工作流层任务状态（新增子系统）

`domain/workflow.go:81-93` 定义任务状态机：`pending → ready → claimed → running → verifying → ready_for_integration → awaiting_approval → integrating → succeeded`，旁支 `retry_wait`、`blocked`、`failed`、`cancelled`。
工作流状态：`draft / active / paused / completed / failed / cancelled`。
执行绑定状态（`domain/workflow_binding.go:37-49`）区分**未知**与**确认失败**：`spawn_unknown`、`stop_unknown`、`recovery_uncertain`、`reconcile_required` 都是正式的耐久状态，不是错误字符串。
