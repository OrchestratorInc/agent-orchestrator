# 设计模式与策略

本项目的模式不是教科书套用，而是**每条都对应一处真实故障或约束**。以下按「模式 → 代码位置 → 为什么必须这样」组织。

## 1. 端口隔离（Port / Hexagonal）

核心只依赖 `internal/ports/` 的窄接口，adapter 实现它们；adapter 是**叶子**，只允许导入 `domain` 和 `ports`。

| 端口 | 实现 |
|---|---|
| `Runtime` | `runtimeselect`（native PTY / ConPTY / tmux） |
| `Workspace` | `gitworktree`、`scratch`、`router` |
| `Agent` | 38 个 agent adapter |
| `ChatConversation` / `ChatController` | 24 个 chat driver |
| `SCM` / `Tracker` | GitHub、GitLab、multi |
| `Reviewer` | 22 个 reviewer adapter |

**为什么**：45+ 个 agent harness 的外部行为各不相同，把它们的差异关在 adapter 内，核心状态机才可能用一套测试覆盖。

## 2. 耐久事实 + 读取时派生（真值最小化）

只持久化 `activity_state`、`is_terminated`、`hibernated_at`、`session_mode`+generation、PR 事实、转移检查点。`working / needs_input / ci_failed / mergeable / merged / no_signal` 全部在读取时算。

派生入口：`service/session/status.go:19 deriveStatus` → `pkg/contract.DeriveStatus`（纯函数，可在 `packages/product-ui` 复用）。

**为什么**：状态多写一次就多一个可能不一致的副本；PR 事实会独立变化，派生读时总能拿到最新组合。

**`no_signal` 有 90 秒宽限**（`status.go:17`）：覆盖 TUI 启动 + 首个带活动的 hook；超过后沉默会话与「hook 管线坏了」无法区分，仪表盘不得自信地显示 idle。

## 3. 观察与动作分离（Observer）

`internal/observe/*` 只轮询和上报，`lifecycle` 只归约写事实，`service` 只派生。

| 观察者 | 周期 | 输出 |
|---|---|---|
| SCM observer | 30s（review thread 更长） | `pr_*` 事实 + 触发 lifecycle nudge |
| Runtime reaper | 5s | `RuntimeFacts{Runtime, Workload}` |
| Usage / activity / artifacts / automations | 各自周期 | 对应事实表 |

## 4. 「探针失败 ≠ 死亡」（保守终止）

`lifecycle.ApplyRuntimeObservation` 只在**全部**条件满足时终止：

1. runtime **与** workload 都明确死亡（`ports.ProbeDead`）；
2. 无近期活动（时间窗 `m.window`）；
3. 无未完成会话变更（`sessionMutationInProgress`）；
4. launch id 匹配当前 launch（防止旧 launch 的回调杀掉新 launch）；
5. 未被 `RuntimeReleasedLaunchID` 标记为「AO 有意释放终端」。

`ProbeFailed`（查询失败）永远不是终止依据；Windows 上 `AccessDenied` / 查询异常一律保留占位。

**为什么**：一次进程查询失败是常见环境问题；误杀会话会丢失用户正在进行的工作。

## 5. CDC 单一事件源（无并行手工发射）

`store` 方法不自己发事件；DB 触发器写 `change_log`，`cdc.Poller` 轮询后由 `cdc.Broadcaster` 同步扇出（订阅者必须非阻塞，需要缓冲就自己投递到 channel）。

`Broadcaster.Subscribe` 的注释明确：**回调在 poller 循环里同步执行，不得阻塞**。

**为什么**：两套事件路径必然漂移；触发器保证「写入成功 ⇒ 事件必达」。

## 6. 代际围栏（Generation Fencing）

每个控制器有 `controller_generation`；旧 Chat 事件按 generation 拒绝，旧 TUI hook 按 runtime launch id 拒绝。工作流层同理：`WorkflowAttemptBinding` 记录 `SessionID` + generation，re-anchor 只在同一 session 的控制器被替换时修身份，**不放宽 fence 语义**。

**为什么**：daemon 重启、控制器切换、同名会话并存时，迟到事件会污染新控制器。

## 7. 提交点单行（Session row as commit point）

接口切换（TUI↔Chat）以 `sessions` 行为唯一提交点：目标启动失败 → CAS 回滚并恢复源；daemon 中途死 → boot 对账按最后提交的 `session_mode` 恢复控制器。

无控制器窗口期的消息进**耐久 outbox**，由最终拥有会话的控制器投递。

**为什么**：两阶段写入若无单一提交点，崩溃后无法判断哪个控制器有效。

## 8. 明确的未知态（不用 nil 表示失败）

工作流绑定状态区分：`spawn_unknown`、`spawn_no_session`、`stop_unknown`、`recovery_uncertain`、`reconcile_required`、`failed_confirmed`。

`execution.Coordinator.bindObservation`：网关返回空 session → 「未知结果」而非「成功 spawn」；readiness 为 exited/failed/unknown → 记录丢失而**不**为新会话背书。

未知态会**闭锁**（`Frozen: true`），不是解封。

**为什么**：把未知当否定会授权错误的重试与清理；把未知当成功会绑定到不存在的会话。

## 9. 租约与唤醒（Chat 休眠边界）

Chat 视图每 10s 续约，租约 30s 失效；30s 清扫捕获后续完成的 turn。只有「最新主 turn 已结算 + 无 Chat 视图 + 原生对话支持 resume + 无转移/待办」时才休眠。

唤醒路径：打开 Chat 标签、发送、或 AO relay。租约续期**只延长**，不重建已失败唤醒。

**为什么**：省掉空闲 provider 进程的内存，同时不切断进行中的 turn。

## 10. 本地套接字 + 有界连接（adapter 内的资源保护）

`adapters/agent/fx/herdr/server.go`：Unix socket / 命名管道，`maxMessageBytes=16KiB`、`maxConnections=32`、accept 失败按 `net/http` 风格指数退避（5ms→1s），socket 只删除**自己创建的**那个 inode。

**为什么**：本地 IPC 也会遇到 EMFILE/ENFILE；无退避会永久放弃后续上报；误删他人 socket 会破坏后继进程。

## 11. 工作流层准入（Admission before side effects）

`scheduler` **只授予执行资格**；进程、Git、供应商副作用全部由 `execution.Coordinator` 持有。准入需通过：能力快照（静态配置不能授权）、预算/资源采样、并发与公平性游标、幂等键。

**为什么**：调度决策必须可回滚且无副作用；副作用集中在协调器才有单一恢复点。

## 12. 幂等与 CAS

- 工作流写操作带 `revision` 与 `workflow_idempotency` 表；`TransitionWorkflowAttemptBinding` 接受 revision，失败即「别人先改了」，返回 unchanged 而非错误。
- 会话行有 `Revision`（DB 拥有），全行写入不会回滚 title / 临时分支等旧读字段。
- CLI 的 `ClientRequestID` + `ClientRequestHash` 绑定一次任务创建，重放只在 `ClientRequestCommitted` 后返回同一行。

## 13. 安全边界即代码（不是 CORS 头）

`httpd/router.go` 中间件顺序固定：`RequestID → requestLogger → recoverer → rendererOrigin → cors → surface`。
rendererOrigin **在 handler 之前**拒绝，因为「CORS 响应头本身不阻止副作用」。
LAN 监听器复用同一 router 但**不暴露** loopback-gated 控制路由；唯一豁免是 `GET /api/v1/identity`（需独立 ADR 才能新增）。

## 14. 降级链（显式 fallback，不静默）

| 场景 | 链 |
|---|---|
| Terminal runtime | 新会话 native PTY → 启动失败回落 tmux；持久 legacy handle 走 tmux；Windows 走 ConPTY |
| Chat 提供者不可用 | 报 typed preflight 失败，移动端提供 TUI 回退选项；不静默切换模式 |
| ChatUI 下一条消息建议 | 支持 fork → 原生 fork；不支持 → 有界 transcript 复制回退 |
| 运行时代码 | 编排层（本仓 dispatch）→ 缺 gate 时显式报错，不假装通过 |
