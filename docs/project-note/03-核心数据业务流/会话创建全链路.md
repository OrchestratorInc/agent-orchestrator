# 会话创建全链路

从「点 New Task」到「agent 第一个 token 输出」的完整路径，含回滚与异步分支。

## 触发点

| 入口 | 路径 | 前置条件 |
|---|---|---|
| 桌面/移动 UI | `POST /api/v1/sessions` | 项目存在（或有 standalone 权限）；harness 已解析 |
| CLI | `ao spawn` → 同一 HTTP 路由 | daemon 存活（`running.json`） |
| 工作流执行器 | `execution.Coordinator` → session manager | 已获得准入 permit 与绑定记录 |
| 自动化 | scheduler → spawn，带 `AutomationRunID` | 自动化规则启用 |
| 预期条目 | New Task 对话框先占位（`TaskPreparation`） | 用户已输入任务文本 |

## 数据流路径

```
POST /api/v1/sessions
 → controllers.SessionsController.Spawn        校验 DTO、解析项目、透传幂等键
 → service/session.Service.Spawn               读模型装配边界
 → session_manager.Manager.Spawn               核心
   ├ 1. 幂等短路        ClientRequestID 命中 → replayClientRequest（仅在已 commit 时）
   ├ 2. 前置校验        项目/standalone 规则、scratch 不准带分支、父会话权限继承
   ├ 3. 解析 harness     项目角色覆盖 → cfg.Harness；未知名直接失败（不落任何持久状态）
   ├ 4. 解析 mode        resolveSessionMode → TUI 或 Chat
   │     Chat 可用性：m.chat==nil / PreflightChat 失败
   │       显式请求 → 报错；隐式默认 → 记录 Warn 后回落 TUI（仅限可回落错误类）
   ├ 5. TUI 额外校验     validateRuntimePrerequisites（Chat 跳过）
   ├ 6. 准入             prepareSpawnAdmission（工作流层时携带 permit）
   ├ 7. 建行             CreateSession / CreateClientRequestSession / CreateAutomationSession
   │                       → DB trigger → change_log → SSE session.created
   ├ 8. 绑账号           agentAccounts.BindSession
   ├ 9. 预留产物目录      reserveArtifactDir（系统提示词要嵌入该路径，必须先存在）
   ├ 10. 构造提示词       buildSpawnTexts（prompt + systemPrompt）；Codex/Claude TUI 额外 resolve 配置
   ├ 11. 系统提示词落盘   prepareSystemPromptFile
   ├ 12. 工作区           prep 复用 / 多仓 createMultiRepoSessionWorkspace / 单仓 createSessionWorkspace
   │                       git worktree add → worktrees/<project-id>/<session-id>
   ├ 13. 工作区准备       provisionWorkspace：符号链接共享文件 + postCreate 命令（如 pnpm install）
   ├ 14. 附件             AddExclude(/attachments/) → writeSpawnAttachments → 提示词追加路径引用
   └ 15. 启动控制器       TUI：runtime Create/Execute + 启动 agent 命令
                          Chat：launchChatController（driver Start/Resume，无运行时句柄）
 → lifecycle.MarkSpawned / MarkChatSpawned       写 activity_state，提交 controller generation
   → DB trigger → SSE session.updated
 → TaskNaming（后台）     生成标题 + 分支 slug，成功启动后异步改名
```

## 关键节点详解

| 节点 | 位置 | 核心逻辑 | 异常处理 |
|---|---|---|---|
| 幂等短路 | `manager.go:996` | `GetSessionByClientRequestID` 命中后核对 `ClientRequestHash` | hash 不符 → 冲突错误；`ClientRequestCommitted` 未置位时不返回该行 |
| harness 解析 | `manager.go:1031` | `effectiveHarness`：spawn 显式 > 项目角色配置 | 未知名在**建行前**失败（否则留孤儿行 + 浪费 worktree） |
| Chat 回退判定 | `manager.go:1090-1104` | 仅 `ErrChatUnsupported/DriverUnavailable/DriverIncompatible/AuthRequired` 且**非显式请求**才回落 TUI | `context.Canceled/DeadlineExceeded` 不回落 |
| Unreal Agent 默认值 | `manager.go:1067` | 无 TUI、无交互审批通道 → 默认 Chat + bypass 权限 | 调用方显式指定则按常规拒绝 |
| 建行 | `manager.go:1157-1193` | 四种创建路径：admitted / client-request / automation / 普通 | 失败包 `ErrSpawnCreate`；automation 已有未完成 launch → 明确报错 |
| 产物目录 | `manager.go:1216` | 必须先存在，因为系统提示词嵌入其路径 | 失败 → `cleanupArtifactDir` + 回滚种子行 |
| 工作区 | `manager.go:1366-1394` | prep 命中复用；多仓为「root + 附加 roots」 | 已有 worktree → `rollbackSeedSpawnWorkspace`；无 worktree → 丢弃种子行 |
| provision | `manager.go:1405` | 符号链接 + postCreate 命令 | 失败回滚工作区，`ErrWorkspaceProvision` |
| 附件 | `manager.go:1415` | CLI agent 不能吃二进制，落盘 + 提示词引用路径 | `AddExclude` 失败即回滚（否则附件会进 git） |
| 模式分叉 | `manager.go:1432` | 之上全部共享；从此 TUI/Chat 只有一个运行 | Chat 失败直接返回，不再回落（已提交行状态由启动路径负责） |

## 异步 Chat spawn（`Async=true`）

Chat 的 API 应答**不等待 Git**：写完种子行就在 `beginAsyncChatSpawn` 处返回，worktree + 控制器在后台继续（`manager.go:1342`）。此时 `provisionState = provisioning`，UI 可见会话并已可排队消息。

失败通过 `provisionState=failed` + `provisionError` 表达，而不是让 API 调用挂住。

## 任务命名（后台）

- 触发：有初始提示词的 git worker（桌面 / CLI / orchestrator）。
- 流程：`startTaskNaming` → agent 的后台任务 driver 生成标题 + slug（20s deadline，但**不阻塞**创建或 agent 启动）。
- 分支：先建在 `ao/<session-id>/root`，成功后异步改名为 `ao/<slug>/root`（命名冲突加数字后缀）。
- 失败/无效输出/达到 4 次调用上限 → 本地 slug 兜底；无可用 ASCII 词 → 用会话 ID 并保留临时分支。
- **已 push 临时分支则跳过改名**（否则 agent 下一次裸 `git push` 会推到另一个远端分支）。
- `branchNaming` 标志从命名开始置位到改名落地/跳过，启动时清除；UI 用 shimmer 遮住临时分支。

## 异常路径

| 异常 | 处理 | 用户可见 |
|---|---|---|
| harness 未知 | 建行前拒绝 | CLI/API 明确「unknown harness」 |
| 显式 Chat 但不可用 | 拒绝，不建行 | typed preflight 错误；移动端提供 TUI 回退 |
| 默认 Chat 不可用 | 回落 TUI + Warn 日志 | 会话正常创建（TUI） |
| 建行后任一后续步骤失败 | 分阶段回滚：prep → 丢弃准备；有 worktree → 回滚工作区；无 worktree → 删种子行；始终清产物目录 | 500，无残留行 |
| 工作流 permit 存在但绑定失败 | `execution.Coordinator` 写 `spawn_unknown`/`failed_confirmed`，**不**伪造成功 | 工作流任务转 `retry_wait` 或 `blocked` |
| 异步 Chat 后台失败 | `provisionState=failed` | 会话卡片显示失败原因 |
