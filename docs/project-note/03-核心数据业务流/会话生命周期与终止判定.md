# 会话生命周期与终止判定

从活跃到终止的唯一写路径，以及「什么时候**不能**判定死亡」。

## 触发点

| 触发 | 来源 | 频率 |
|---|---|---|
| 运行时探针 | `observe/reaper` `Tick` | 5s |
| agent 活动信号 | `ao hooks <agent> <event>` → agent adapter → lifecycle | 事件驱动 |
| Chat 控制器信号 | chat controller → lifecycle | 事件驱动 |
| SCM 观察 | `observe/scm` `Poll` | 30s |
| 显式操作 | `Kill` / `Restore` / `Cleanup` | 用户 / API |
| 启动对账 | `RestoreAll`、boot reconciliation | daemon 启动 |

## 数据流路径

```
外部事实
 ├ runtime probe  → ports.RuntimeFacts{Runtime, Workload, LaunchID, ObservedAt}
 ├ TUI hook       → ActivitySignals（按 runtime launch id 栅栏）
 ├ Chat events    → ChatSignals（按 controller generation 栅栏）
 └ SCM poll       → pr_* 事实 + nudge 触发
        ↓
lifecycle.Manager（唯一写路径）
 ├ ApplyRuntimeObservation     runtime/workload 探针与终止判定
 ├ ApplyActivitySignal         hook 活动 → activity_state
 ├ MarkSpawned/MarkChatSpawned 启动提交
 ├ MarkTerminated             显式终止
 └ 归约后写 sessions 行
        ↓
DB trigger → change_log → CDC → SSE / 终端 fanout
        ↓
service/session.deriveStatus（读取时派生展示状态）
```

## 终止判定（全部满足才终止）

1. **launch 匹配**：`f.LaunchID == cur.Metadata.RuntimeLaunchID`（或当前无 launch id）。旧 launch 的回调**永远**不杀新 launch。
2. **明确死亡**：`runtimeClearlyDead` = `f.Runtime == ProbeDead` **且** 无近期活动（`lifecycle/runtime.go:25`）。
   - `ProbeFailed` / `ProbeUnknown` / 查询异常 → **不是**死亡。
3. **无进行中的会话变更**：`sessionMutationInProgress(id)` 为假。
4. **未被有意释放**：`RuntimeReleasedLaunchID == currentLaunch` 且 `ActivityExited`（agent 退出但会话保留）→ 不视为崩溃。
5. **workload 语义**：`Runtime=Alive && Workload=Dead` → 只写 `ActivityExited`，不终止（受监督的工作负载死亡由 launch generation 独立围栏）。

并发保护：终止分两步——先读出 `terminationRevision` + `terminationLaunch`，再以 CAS 复核 revision/launch/死因才开始写；期间任何变化都放弃本次终止。

## 关键节点详解

| 节点 | 位置 | 核心逻辑 | 异常处理 |
|---|---|---|---|
| Reaper Tick | `reaper.go:153` | 遍历所有未终止会话，逐个 `probeOne` | 单会话探针失败只记日志，不影响整批 |
| **大规模死亡熔断** | `reaper.go:181` | `dead >= 5` 且 `dead > 50%` 被探测数 → 判定为「故障而非 N 次死亡」，把本批 dead 全部降级为 `ProbeFailed` | 日志 Error，本批结论作废，等下一轮 |
| Chat 会话跳过探针 | `reaper.go:208` | Chat 无终端运行时，句柄缺失不是异常 | 不产生 ProbeFailed 噪音 |
| 活动栅栏 | `lifecycle/manager.go:455` | 未终止 + launch 匹配才继续 | 否则早退 |
| 终止写 | `manager.go:493-512` | 第二次 mutate 做完整 CAS 复核 | 任一条件不满足 → 不终止 |
| 终止后清理 | `manager.go:516-523` | `SessionEnded` 遥测 + `reapSessionContainers`（reaper 观察到的死亡也必须走容器回收） | 未回收会遗留 Docker 容器 |
| 展示状态 | `service/session/status.go:19` | 派生，见下 | — |

## 展示状态派生优先级（高 → 低）

```
is_terminated?  → PR merged ? merged : terminated
activity ∈ {waiting_input, blocked} ? → needs_input
有 PR 事实?     → PR pipeline（ci_failed / draft / changes_requested /
                                merge_conflict / mergeable / approved /
                                review_pending / pr_open）
activity == active ? → working
支持信号但无信号（超 90s 宽限）? → no_signal
否则 → idle
```

多 PR 时「最差者胜」：`deriveStatus` 在所有独立 PR 上做聚合，堆叠子 PR 从聚合中豁免（`pkg/contract/status.go`）。

## 异常路径

| 异常 | 处理 | 不要做什么 |
|---|---|---|
| 进程查询失败（Windows AccessDenied 等） | 保留占位、保留锁/描述符/run-file | 不要当死亡清理 |
| 大面积探针同时失败 | 熔断，本批降级为 ProbeFailed | 不要批量标 terminated |
| daemon 重启 | `RestoreAll` 按 `session_mode` 恢复控制器 | 不要手工删 SQLite 行/host 描述/工作树 |
| 终止期间 revision 变化 | 放弃终止，等下一轮 | 不要用旧读强行写入 |
| Chat 会话无 runtime handle | 跳过探针 | 不要报异常 |
