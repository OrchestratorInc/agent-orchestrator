# 接口切换（TUI ↔ Chat）

在**同一个 AO 会话**内替换控制器，而不是新建会话。会话 ID、项目、工作区、生命周期事实、provider 原生会话 ID 全部不变；只有 mode 所属的控制器换。

## 触发点

- 桌面/移动点击「Switch to chat UI」/「Switch to terminal UI」。
- `POST /api/v1/sessions/{id}/interface-transition`（`target` + `policy`）。
- 前置：harness 必须通过 `AgentInterfaceHandoff` 能力（TUI resume id 与 Chat protocol id 证明是同一段原生对话）。目前只有 Claude Code 与 Codex 满足；仅注册了 Chat driver 不够。

## 数据流路径

```
POST interface-transition{target, policy}
 → Manager: Claim 唯一活跃 transition（CAS，防并发切换）
 → 源头栅栏
     Chat 源：ArmChatHandoff 关闭 intake、停止队列派发
     TUI 源：门禁新终端输入（terminal.Manager.BeginInputDrain/HoldInput）
 → 目标 preflight（二进制/认证/协议）
 → policy=drain         → 等待已接受的工作完成
   policy=interrupt     → 取消排队 Chat turns → provider 取消活跃 turn → 短暂 flush
 → 停止源控制器并等待 shutdown
 → lifecycle.CommitControllerEpoch(source, target, nativeID)
     CAS 写 sessions.mode + 清旧 generation/handles + idle 事实
 → 目标 native resume（同一原生会话 ID）
 → 持久化新 handle/generation，transition=completed
 → CDC session_updated → UI 换渲染器
```

## 阶段（`domain/session_interface_transition.go:48-70`）

`requested → preflighting → draining → source_stopping → source_stopped → target_starting → activating → completed`，旁支 `failed` / `cancelled` / `recovery_required`。

这些是**耐久**检查点：daemon 死在任意阶段，boot 对账能判断该继续、回滚还是标记 `recovery_required`。

## 关键节点详解

| 节点 | 位置 | 核心逻辑 | 异常处理 |
|---|---|---|---|
| Claim | `interface_transition.go` | `CreateSessionInterfaceTransition` 唯一性 + `...After` 校验前驱 | 并发第二个请求被拒 |
| Chat 源栅栏 | `controller.go:189-207` | `controllerHandoff` 三态：`none`/drain/interrupt | intake 关闭后新 send 报 `ErrControllerHandoff` |
| TUI 源栅栏 | `terminal.Manager` | 输入租约 + drain 窗口 | 见到可见草稿 → 失败且源原样保留 |
| 静态判定（TUI drain） | `interface_transition.go:17-26` | 轮询 150ms、静默 settle 750ms、3 次连续 idle 采样、stale idle 上限 5s、stop 上限 15s、单步 45s | 超时报 `errDrainQuiescenceUnverified`；有 provider 决策待答时报 `errDrainDecisionPending` |
| 提交点 | `lifecycle.CommitControllerEpoch` | **sessions 行是唯一提交点**；CAS mode，清旧 generation/handle | 目标启动失败 → CAS 回滚 + 恢复源 |
| 目标 resume | `chat.Service` / runtime | 同一原生会话 ID resume | resume-only provider（不重放历史）→ **fail closed** |
| outbox | `session_interface_transition_messages` | 无控制器窗口期的消息耐久排队 | 由最终拥有会话的控制器投递；Chat 重试用稳定幂等键 |

## 交接的历史屏障

- 原生历史屏障 = 可信原生检查点 ∩ 最近一次「已完成 AO turn」（在活跃 provider scope 内）。
- 更新的已完成 turn 可以压过更旧的 legacy hook 事实；hook 时间戳必须证明它**早于**该 turn，重复文本不算证据。
- Codex 按 fork 祖先关系跳过已复制前缀，但仅当 stable item id 与内容完全匹配；未知祖先或内容变化 → 全量保留。

## 异常路径

| 异常 | 处理 |
|---|---|
| 目标 preflight 失败 | CAS 回滚，源继续运行；消息仍在 outbox |
| drain 无法证明静默 | `errDrainQuiescenceUnverified`，源未动，提示重试 |
| TUI 有等待中的决策 | `errDrainDecisionPending`，要求先在终端回答或改用 cancel |
| daemon 中途死亡 | boot 对账：继续 / 回滚 / `recovery_required` |
| 迟到事件 | Chat 侧按 controller generation 拒绝；TUI 侧按 launch id 拒绝 |
| resume-only agent 的 TUI→Chat | 不静默改用全新 Chat provider，直接失败 |
