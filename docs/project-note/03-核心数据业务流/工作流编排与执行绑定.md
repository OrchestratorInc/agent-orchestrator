# 工作流编排与执行绑定

多 Agent 工作流层的主动线：规划 → 准入 → 执行绑定 → 质量门禁 → 集成。这是本仓相对上游新增的能力，建立在既有 Session 之上。

## 触发点

| 触发 | 入口 | 说明 |
|---|---|---|
| 用户提交需求 | `POST /api/v1/workflows` → `workflow.Service` | 生成 DAG 候选 |
| 候选规划 | 从既有 Chat attempt 的 turn 输出解析 | **不另开 provider loop**，复用已持久化的 Chat 输出 |
| 周期扫描 | `scheduler` `ScanInterval=15s` | 找可执行任务 |
| 准入请求 | `scheduler.Service` → `workflow.Claim` 闭包 | 只授予资格 |
| 执行 | `execution.Coordinator` | 真正 spawn 会话、绑定、写事实 |
| 用户干预 | `intervention.Coordinator`：queue / steer / stop | 受 generation 围栏 |
| 质量门禁 | `qualitygate.Service` | 独立评审 + 门禁判定 |
| 集成 | `integration` / `taskcommit` | 受策略控制的合并与推送准备 |

## 数据流路径

```
workflow.Service
 ├ planning：候选 DAG → 受 domain.WorkflowGraphLimits{MaxTasks:50, MaxDepth:12, MaxFanOut:8} 校验
 ├ materialization：确认后落 tasks / edges / repos 行
 └ replanning：受控重规划（有 stop 干预时终止）

scheduler.Service
 ├ MaintainLeadership：持久 CAS 抢领导权，30s 租约 / 10s 续租；**绝不自行标记恢复完成**
 ├ 资源采样（5s 窗口）：并发上限、预算
 ├ 公平游标：按 Workflow 分页（CandidateLimit=100），避免大工作流遮蔽其他
 └ Claim（ClaimLimit=3）：只授予执行资格 + 预算预留，无副作用

execution.Coordinator
 ├ BindAttempt → 调 gateway spawn（真会话）
 ├ bindObservation：把会话 readiness 映射为绑定状态
 │    ├ 空 session id            → spawn_unknown（未知，不是成功）
 │    ├ exited/failed/unknown    → failed_confirmed / reconcile_required，**永不为该会话背书**
 │    ├ ready + repo 证据齐全     → bound_ready → 写入 repo bindings
 │    └ 同一 session 控制器被换   → re-anchor 只修身份，不放宽 fence
 └ 幂等：绑定带 revision，CAS 失败视为「别人先改」→ 返回 unchanged

collaboration.Coordinator
 ├ ResolveCaller：身份由服务端推导，**永不**来自请求输入
 ├ 工作流终态（completed/failed/cancelled）拒绝新消息与任务请求
 └ CreateTaskRequest：只记录请求，无调度效果（不写 task/edge/repo 行）

intervention.Coordinator
 ├ Steer：必须指名 target turn；需要 harness 的 steer 能力证据
 ├ Queue：不要求 steer 能力（排队是 AO 自身行为），回执写 queued 而非 sent
 └ Stop：停止已定位会话并推进绑定状态
```

## 关键节点详解

| 节点 | 位置 | 核心逻辑 | 异常处理 |
|---|---|---|---|
| 领导权 | `scheduler/service.go:77` | CAS 获取/续租，fence epoch 不符即失效 | `ErrSchedulerFence`；续租期间公平游标推进也会改 revision，只有任期丢失才清身份 |
| 准入无副作用 | `scheduler/service.go` | 进程/Git/供应商副作用全在 `execution.Coordinator` | 失败可安全重试 |
| 图限制 | `collaboration/coordinator.go:172` | 50 任务 / 12 层 / 8 扇出 | 超限拒绝 |
| 绑定状态机 | `domain/workflow_binding.go:37-49` | 14 状态，含 4 个显式未知态 | 未知态 `Frozen: true` 闭锁 |
| 仓库门禁 | `execution/coordinator.go:681` | 多仓总严格校验；单仓空 worktree 列表不算缺失证据 | 不满足 → `reconcile_required` |
| re-anchor | `execution/coordinator.go:761` | 同会话控制器被替换时修 generation | 只修身份，旧 generation 仍被所有 fence 拒绝 |
| 幂等 | `workflow_idempotency` 表 + revision | 重放返回原结果 | CAS 失败 ≠ 错误 |
| 消息授权 | `collaboration/coordinator.go:212` | 人类 claim 不增权（丢失 agent 字段） | 未授权 → `ErrCollaborationNotAuthorized` |
| steer 能力 | `intervention/coordinator.go:285` | 未知 harness 无能力证据 → 不授权 | `CapabilityReasonNotProbed`，并提示队列可用 |

## 状态机

**工作流**：`draft → active → (paused) → completed | failed | cancelled`

**任务**（`domain/workflow.go:81-93`）：
`pending → ready → claimed → running → verifying → ready_for_integration → awaiting_approval → integrating → succeeded`，旁支 `retry_wait / blocked / failed / cancelled`

**执行绑定**（`domain/workflow_binding.go`）：
`unbound → intent_persisted → spawn_requested → session_provisioning → bound_ready → running → stop_requested → stop_confirmed`，未知/回收态 `spawn_unknown / stop_unknown / recovery_uncertain / reconcile_required`，失败态 `failed_confirmed`。

## 异常路径

| 异常 | 处理 | 禁止 |
|---|---|---|
| 网关返回但无 session | `spawn_unknown`，冻结 | 不要当成功 spawn |
| 绑定 CAS 失败 | 返回 unchanged（别人先改） | 不要覆盖 |
| 多仓 worktree 缺失 | `reconcile_required` | 不要继续派发 |
| 领导权丢失 | 清 fence，本轮不授予资格 | 不要盲轮询重试授予 |
| 未知 harness 的 steer | 拒绝并提示 queue | 不要按名字猜能力 |
| 工作流终态 | 拒绝新消息/任务请求 | 不要复活工作流 |
