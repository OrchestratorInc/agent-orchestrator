### fx (experimental)

Install fx from Settings → Harnesses on macOS or Linux (expected at
`~/.local/bin/fx`; on Windows use WSL), then spawn it in Terminal UI mode.
fx Chat is not supported.

```bash
ao spawn --name fx-task --agent fx --mode tui
```

## Chat versus Terminal UI

Unreal Agent is Chat-only; the other worker adapters provide a terminal interface. These harnesses have structured Chat drivers:

| Harness | Chat transport |
| --- | --- |
| `codex` | Codex native app-server |
| `claude-code` | `claude-agent-acp` using the user's Claude executable |
| `opencode` | Native ACP (OpenCode 1) |
| `opencode-v2` | Native ACP (OpenCode 2) |
| `droid` | Native ACP |
| `kimi` | Native ACP |
| `kimchi` | Native ACP |
| `pi` | Separately installed ACP adapter; explicit bypass permissions required |
| `cursor` | Native ACP |
| `omp` | Native ACP |
| `qwen` | Native ACP |
| `unreal-agent` | Built into AO |
| `deepseek-harness` | Native ACP (`dsh --profile acp`) |

Every other harness is Terminal UI-only. Choose the initial interface with `ao spawn --mode chat|tui`. Compatible Claude Code and Codex sessions can hand off between Chat and Terminal UI while retaining the AO session and worktree.

Qwen Chat needs version 0.16 or newer; OMP Chat needs version 15 or newer. MiMo Code needs version 0.1.14 or newer and is Terminal UI-only, as is Gemini. Unreal Agent is built into AO for macOS/Linux, is Chat-only, and requires bypass permissions because it has no interactive approval flow. DeepSeek Chat uses `dsh --profile acp`. Check readiness and the provider options offered by your installed AO version before launching.

Chat registration does not imply interface handoff support. Use the switch action and its disabled reason in the session UI. Experimental reviewer modes and prompts do not sandbox tools or network access.

## Choosing and configuring a harness

```bash
ao project set-config my-app --worker-agent codex
ao spawn --project my-app --name auth-fix --agent claude-code --mode chat
```

`--agent` and `--harness` are aliases. The `set-config` example replaces the full config; preserve existing fields before applying it. Project configuration may also specify model, effort, permission mode, environment, prompt rules, and separate worker/orchestrator defaults. The CLI's project-config mirror currently omits `effort`: `ao project get --json` cannot show it, and `ao project set-config` may drop an existing value. Use project settings in the desktop app or the daemon API to preserve or change effort until the CLI mirror is fixed. Use `ao project set-config --help` for the fields it supports.
