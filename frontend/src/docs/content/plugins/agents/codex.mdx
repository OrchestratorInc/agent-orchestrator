title: Codex
description: Built-in Terminal UI and native app-server Chat support for the user's Codex installation.
---

Orchestrator uses the locally installed `codex` executable and Codex-owned authentication.

```bash
ao agent ls
ao spawn --project my-app --name codex-task --agent codex --mode chat
```

## Interfaces

- **Terminal UI:** runs the native Codex CLI in the session worktree.
- **Chat:** connects to Codex's native app-server protocol and persists the provider conversation identity with the Orchestrator session.

Codex supports the same capability-gated Chat/Terminal UI handoff as Claude Code. The Orchestrator session and worktree remain stable across a compatible handoff.

Orchestrator performs bounded installation and authentication probes before spawn. Use `--skip-agent-check` only to bypass that advisory CLI preflight; daemon validation remains authoritative.

## Accounts

Open **Settings → Agents → Codex → Account** to see the Codex sign-ins, their ChatGPT workspaces, and their usage limits. Under **Add account**, choose **ChatGPT in browser** or **Device code** and select the workspace in ChatGPT. If you already know the workspace ID, enter it to restrict sign-in to that workspace. Repeat for each workspace, even when they share an email address. Orchestrator shows the workspace name when Codex reports one, otherwise a short workspace ID if available. If neither is available, it says the workspace is unknown.

If the list shows short IDs, update the Codex CLI: version 0.172.0 can report the workspace name for your existing sign-in. The plan comes from Codex's account or usage response. If neither reports it, Orchestrator does not infer a plan from quota or workspace name.

Codex manages sign-in in a separate Codex home for each saved workspace. Orchestrator stores the workspace ID, not a separate copy of the credentials. Conversations and local history stay shared.

New tasks start on the account marked **Default for new tasks** unless you pick another account in the task composer. Sessions on different accounts run side by side. A session's Summary shows its account: choosing another restarts the agent on that account in the same conversation, and Orchestrator asks before it stops a turn that is still running. Adding, removing, or choosing a default account in Orchestrator never changes the login Codex uses outside Orchestrator.
