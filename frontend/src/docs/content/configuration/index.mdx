Orchestrator keeps its durable state under `~/.ao`. The daemon stores projects, sessions, pull-request facts, notifications, and typed project configuration in SQLite under `~/.ao/data`; `~/.ao/running.json` lets the desktop app and CLI find the running daemon.

The desktop app is the normal place to add projects and change settings. The CLI talks to the same daemon API when you need a scriptable path.

## Add a project

In the desktop app, choose **Add project** and select a local repository. From the CLI:

```bash
ao project add --path /absolute/path/to/repo
```

To set the default agents while registering the project:

```bash
ao project add --path /absolute/path/to/repo \
  --worker-agent codex \
  --orchestrator-agent claude-code
```

Orchestrator also supports workspace projects, which contain a root repository and direct child repositories:

```bash
ao project add --path /absolute/path/to/workspace --as-workspace
```

Standalone workers support projectless work: `ao spawn --standalone --agent codex --name notes`. Existing Scratch projects also use Orchestrator-managed directories without branches or PR claims.

## Inspect and update configuration

```bash
ao project ls
ao project get <project-id>
```

Use Project Settings in the desktop app for interactive changes. The CLI's `set-config` flags change only the fields they name, while `--config-json` replaces the entire project config. Before using it, read [the CLI update warning](/configuration/projects#update-from-the-cli). The CLI ignores unknown JSON keys.

Project configuration has typed fields for the base branch, session prefix, environment variables, symlinks, setup commands, worker and orchestrator agents, agent options, project rules, reviewers, automatic review, trusted repository URLs, issue intake, and container cleanup. The daemon API rejects unknown fields. The CLI's `--config-json` decoder ignores unknown keys, so a typo can clear existing settings when the full config is replaced.

See [Projects](/configuration/projects) for the current field reference.

## 调度与容量

在 **设置 → 调度与容量** 中调整全局或各代理的并发上限，范围为 1–10。默认全局为 3、单个代理为 2；编排器和工作会话共用这些名额，空闲但尚未终止的会话仍占用名额。页面同时显示当前占用与动态容量，工作流的“预算与容量”页提供相同配置。

全局策略的“资源限制”开关控制是否根据 CPU 和可用内存限制新增会话。开启时可调整 CPU 恢复、软限流和硬限制阈值，以及内存可用比例的软/硬阈值和最低保留 GiB。默认可用内存低于 25% 会逐步降低容量，低于 15% 或不足 2 GiB 会停止新增准入。关闭后，资源负载或采样不可用不会阻止启动；全局/单代理并发上限、授权和预算检查继续生效。

保存会沿用桌面审批流程，并立即更新当前 daemon 的策略，无需重启。策略持久化保存在该 daemon 的数据库中；降低并发不会终止已有会话，只会限制后续启动。关闭资源限制后，启动前需要自行留意机器负载。

## Daemon environment

The primary daemon listener is always loopback-only and unauthenticated. Its bind host is not configurable. Useful environment variables include:

| Variable | Default | Purpose |
| --- | --- | --- |
| `AO_PORT` | `3001` | REST, events, terminal mux, health, and control port |
| `AO_DATA_DIR` | `~/.ao/data` | Durable daemon data |
| `AO_RUN_FILE` | `~/.ao/running.json` | Daemon discovery file |
| `AO_REQUEST_TIMEOUT` | `60s` | REST request timeout |
| `AO_SHUTDOWN_TIMEOUT` | `10s` | Graceful shutdown deadline. It also scales how long a starting daemon waits for a previous daemon to release the data directory (9 × this + 18 s) |
| `AO_ALLOWED_ORIGINS` | packaged desktop origin | Additional trusted browser origins |
| `AO_TRACKER_INTAKE` | `off` | Enables the issue-intake observer; a project's own `trackerIntake` cannot enable it alone |

Do not set `HOST=0.0.0.0` or proxy the primary daemon to a network. For phone access, use the separate authenticated listener created by **Connect Mobile**. See [Remote access](/configuration/remote-access).

## Chat and Terminal UI defaults

Every session commits to one interface at a time:

- **Chat** uses a structured, runtime-less provider controller with durable messages, activities, approvals, and usage.
- **Terminal UI** runs the agent's native terminal interface through Orchestrator's terminal runtime.

Choose the default for new sessions in **Settings → General**. A choice made for a specific task takes precedence. If a requested interface is unavailable, Orchestrator uses Terminal UI as its compatibility fallback.

Project `agentConfig.mode` selects a provider execution mode. It does not select Chat or Terminal UI. Choose the interface in the new-session flow or with `ao spawn --mode chat|tui`. Compatible Claude Code and Codex sessions can switch interfaces without changing the Orchestrator session or worktree.

Manage recurring tasks in **Automations**, reusable project actions in **Cues**, installed provider readiness in **Settings → Harness**, and persistent profiles/imports in **Settings → Browser**. These features have their own settings/resources rather than legacy YAML keys.
