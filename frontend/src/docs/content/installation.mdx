On your phone, install [Orchestrator Mobile for iPhone or iPad](https://apps.apple.com/app/ao-mobile/id6792552173) or [Orchestrator Mobile for Android](https://play.google.com/store/apps/details?id=aoagents.dev). <span id="install-on-macos" />
## Install on macOS

The macOS downloads above are the **Stable** disk images (`.dmg`). To install one:

1. Open the downloaded `Orchestrator-darwin-arm64.dmg` (Apple silicon) or `Orchestrator-darwin-x64.dmg` (Intel). Finder opens a window named **Orchestrator** that shows the app and an **Applications** folder.
2. Drag **Orchestrator** onto **Applications**. If Orchestrator is already installed, quit it first, then choose **Replace** when Finder asks. Your projects, sessions, and settings stay in `~/.ao`, so replacing the app keeps them.
3. Eject the disk image: choose the eject button beside **Orchestrator** in the Finder sidebar, or drag the disk image to the Trash. You can then delete the downloaded `.dmg`.
4. Open **Orchestrator** from the Applications folder, Launchpad, or Spotlight.

Always open the copy in Applications, not the one on the disk image or in Downloads. The updater updates only the installed copy, so a copy anywhere else stays on the version you downloaded.

Each release also publishes macOS `.zip` files. The updater installs from them; they aren't meant for a first install. Double-clicking a zip extracts the app next to it, usually in Downloads, so opening it there leaves a second copy of Orchestrator beside the one in Applications.

<span id="nightly-on-macos" />
### Nightly on macOS

Nightly builds have no disk image. Their direct macOS downloads are `.zip` files only. To use Nightly without running a copy from Downloads, install Stable from the disk image as described above, then switch channels in the app:

1. Open **Settings → Updates**.
2. Set **Updates channel** to **Nightly**, labeled Nightly (Pre-release).
3. Choose **Update** to download the newest nightly, then choose **Restart & install**. The updater replaces the app in Applications.

To go back, set **Updates channel** to **Stable**. The updater never installs an older build, so you move to Stable with the first stable release newer than your nightly.

If Orchestrator is already installed, switch channels in the app rather than replacing it by hand. If you download a nightly `.zip` instead, move the extracted app into Applications before you open it: quit Orchestrator if it is running, drag the extracted **Orchestrator** from Downloads onto **Applications**, and choose **Replace** if Finder asks. Your data in `~/.ao` stays. Then delete the zip and any copy left in Downloads, and open Orchestrator from Applications.

## Install with a package manager

The desktop download above is the recommended install. You can also install the same desktop app with a package manager.

On macOS, use the official Homebrew cask. It installs the app and links the `ao` command into Homebrew's `bin` folder, so `ao` is on your `PATH`:

```bash
brew install --cask agent-orchestrator
```

On Windows, use winget:

```powershell
winget install --id OrchestratorInc.AgentOrchestrator -e
```

The desktop app normally updates itself. To refresh a package-manager install, upgrade it the same way:

```bash
brew upgrade --cask agent-orchestrator
```

```powershell
winget upgrade --id OrchestratorInc.AgentOrchestrator -e
```

If you installed from the older `agentwrapper/tap` tap, switch to the official cask, which is the one that links `ao`:

```bash
brew uninstall --cask agentwrapper/tap/agent-orchestrator
brew install --cask agent-orchestrator
```

<span id="where-ao-is" />
## Where the `ao` command is

The desktop app bundles the `ao` CLI. You don't need it for normal desktop use, but scripts and coding agents use it to drive Orchestrator.

| How you installed | Where `ao` is |
| --- | --- |
| Homebrew cask (macOS) | On your `PATH` as `ao`, linked from the app bundle |
| Disk image or zip (macOS) | `/Applications/Agent Orchestrator.app/Contents/Resources/daemon/ao` |
| Windows installer or winget | `resources\daemon\ao.exe` inside the app's install folder |
| Linux `.deb` or `.rpm` | `resources/daemon/ao` inside the app's install folder |

Without the cask, call `ao` by its full path, or add an alias to your shell profile. An alias works only in your interactive shell; scripts don't see it, so they should use the full path or a linked `ao`:

```bash
alias ao='"/Applications/Agent Orchestrator.app/Contents/Resources/daemon/ao"'
```

To use the short `ao` name without the cask on macOS, or on Linux with a `.deb` or `.rpm` install, turn on **Developer mode** in **Settings → General** and choose **Link** beside **Global ao command**. AppImage installs cannot be linked. See [Run the CLI](/cli#run-the-cli).

Run `ao status` to confirm it works. Commands that act on projects and sessions need the desktop app open, because the app runs the daemon they talk to. To drive Orchestrator from a coding agent, see [Use Orchestrator from your coding agent](/agent-setup).

## Prerequisites

| Tool | When you need it | Why |
| --- | --- | --- |
| Git | Repository projects | Creates and manages isolated worktrees and branches. |
| GitHub CLI `gh` | GitHub projects | Uses your existing authentication for repository and pull-request operations. |
| External coding agent (called a harness in Orchestrator) | Agent sessions that use an installed CLI | Install a supported tool such as Claude Code, Codex, Cursor, Aider, or OpenCode. See the [agent catalog](/plugins/agents) for the current list and interface support. Unreal Agent is built into Orchestrator for Chat on macOS and Linux. |
| tmux | macOS preflight and legacy/fallback terminal sessions | Desktop macOS/Linux packages include it. Source launches may need system tmux; see [Runtime](/plugins/runtimes). |

Orchestrator uses the coding agents and sign-ins already installed on your computer. **Settings → Agents** shows each supported agent's readiness and offers **Install** and **Login** for agents that support them. Unreal Agent is a built-in Chat-only exception with its own platform and permission limits. See the [agent catalog](/plugins/agents).

## Set up Orchestrator

<Steps>
<Step>

### Install and open the desktop app

Choose the download for your platform above, install it, and open **Orchestrator**. On macOS, drag it to Applications first, as described in [Install on macOS](#install-on-macos). The app starts and supervises the local Go daemon automatically.

</Step>
<Step>

### Authenticate GitHub

For a GitHub repository, [install GitHub CLI](https://cli.github.com/) if needed, then sign in:

```bash
gh auth login
gh auth status
```

Use an account that can read the repository and perform the branch and pull-request actions you expect the agent to take.

For GitLab, sign in with a GitLab token or `glab`. See [source-control setup](/plugins/scm).

</Step>
<Step>

<span id="install-and-sign-in-to-an-agent" />

### Install and sign in to an external agent

Open **Settings → Agents** and select the agent you want to use. If it isn't installed, choose **Install** (or **Open installation guide**). If it isn't signed in, choose **Login** and finish the sign-in that opens. The agent is ready when Settings shows it installed and signed in. An agent you already use and are signed in to is detected automatically.

If you prefer the terminal, sign in with the agent's own command instead, for example `codex login`, or run `claude` and use `/login`. Then run `ao agent ls --refresh` so Orchestrator checks again.

If you use the built-in Unreal Agent, skip this step and choose it for a Chat session on supported macOS or Linux.

Chat support depends on the harness and installed version; see the [agent capability catalog](/plugins/agents#chat-versus-terminal-ui).

</Step>
<Step>

### Add a project

In the desktop app, choose **Add project** and select an existing local Git repository. Orchestrator registers it without moving your original checkout. Each worker session gets its own isolated worktree.

</Step>
</Steps>

You can also start a projectless standalone task for work that needs no repository. The optional CLI form is `ao spawn --standalone --agent codex --name notes --prompt "Draft release notes"`; standalone workers cannot claim a PR or take Git/project flags.

## Where Orchestrator stores data

All Orchestrator application state lives under `~/.ao` by default, including the daemon database, run file, managed worktrees, Electron browser data, and mobile pairing configuration. Advanced installations can override daemon paths with `AO_DATA_DIR` and `AO_RUN_FILE`.

## Common installation problems

<Accordions>
	<Accordion title="No agent is available">
		Open **Settings → Agents**, select the agent, and use **Install** or **Login**. From a terminal, sign in with the agent's own login command, then run `ao agent ls --refresh`. If a newly installed agent still doesn't appear, quit and reopen Orchestrator so its daemon picks up your updated shell `PATH`. Unreal Agent is built into Orchestrator for Chat on supported macOS and Linux; choose it directly instead of installing a CLI.
	</Accordion>
	<Accordion title="GitHub data is missing">
		Run `gh auth status`. Confirm the active account can access the repository and its pull requests.
	</Accordion>
	<Accordion title="Terminal UI cannot start on macOS or Linux">
		Packaged builds include tmux. New sessions normally use native PTY hosts; macOS still checks tmux availability and older sessions may need it. See [runtime diagnostics](/plugins/runtimes/tmux) for source installs and fallback behavior.
	</Accordion>
	<Accordion title="The `ao` command is not found">
		The desktop app does not require it. The app bundles `ao` but doesn't add it to your `PATH`; see [where the `ao` command is](#where-ao-is). The official Homebrew cask links it for you. If an older `ao` from the legacy npm package comes first on your `PATH`, `ao doctor` reports which `ao` it found.
	</Accordion>
	<Accordion title="macOS says the developer cannot be verified">
		In Finder, right-click Orchestrator, choose Open, then choose Open again in the confirmation dialog. If macOS still blocks the app, run these diagnostics and include the output when opening an issue:
		```bash
		sw_vers
		codesign -dvvv "/Applications/Agent Orchestrator.app"
		spctl -a -t exec -vvv --ignore-cache --no-cache "/Applications/Agent Orchestrator.app"
		log show --last 10m --predicate 'subsystem == "com.apple.syspolicy"'
		```
	</Accordion>
</Accordions>
